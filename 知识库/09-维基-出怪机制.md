## 二、出怪类型（本次选卡允许哪些僵尸出现）

### 2.1 存哪里
`[[[6a9ec0]+768]+54d4]` 起连续 **33 个 bool**，`true` = 准许。

### 2.2 六步生成算法（务必按序理解）

```
1. 设定要出「普僵」
2. 产生 0~4 伪随机整数：等于 0 → 读报，否则 → 路障
3. 轮数 < 8 → 剩余出怪类型数 = 轮数 + 1；否则 = 9
4. 产生 0~33 伪随机整数；若该类未设定且未被禁止 → 设定，进第 5 步；否则重摇
5. 已设定的类型数 = 第 3 步的剩余数？是 → 第 6 步；否 → 回第 4 步
6. 忽略摇旗、僵博（强制 false）
```

**推论**：
- **"读报路障不同出"是谣言** —— 第 2 步没被选中的那个，后面还能被选中。
- 第 6 步决定"几怪"：都没选中 → **11 怪**；选中其一 → **10 怪**；都选中 → **9 怪**。
- "禁止出"清单：伴舞/鸭子/雪橇/雪人/小鬼、植物僵尸、**黑夜的冰车**、**非后院的潜水/海豚**、
  **屋顶的舞王/矿工**、`轮数<2` 的冰车/白眼、`轮数<5` 的红眼。
- 部分僵尸**无需准许**：旗帜（固定）、雪人（极小概率随机）。

### 2.3 轮数

```
轮数 = 选卡时已完成 flag 数 / 2 − 1
```

随机数生成器 **MT19937**，种子 = 四项相加：
```
[[[6a9ec0]+82c]+20]              // 用户序号
[[[6a9ec0]+768]+561c]            // 出怪种子
[[[[6a9ec0]+768]+160]+6c] * 65   // 完成选卡次数 * 101
[[6a9ec0]+7f8]                   // 游戏模式
```

> 注意：`561c` 在非生存模式是"程序窗口打开时间"，所以生存模式的出怪**可复现**。

### 2.4 概率公式（比查表好用）

设 `a` = 可出怪类型数，`b` = 剩余出怪类型数：
```
路障概率 = 0.8 + 0.2 × b/a
读报概率 = 0.2 + 0.8 × b/a
其他概率 = b/a
```
种类数三种情况：
```
b(b−1) / a(a−1)           // 少一种
b(a−b)·2 / a(a−1)         // 正好
(a−b)(a−b−1) / a(a−1)     // 多一种
```
`轮数 ≥ 5` 时六大场地的 a 值：**18 / 17 / 20 / 20 / 16 / 16**（白天/黑夜/后院/屋顶…按序）。
`轮数 ≥ 8` 时 b = **9**。

**实用结论**：轮数越大，"其他僵尸"的种类越多 → 出怪越杂、越难。
后院 `a=20` 最大 → 后院最容易出满 11 怪。

## 三、出怪列表（真正决定刷什么）

- 位置：`[[[6a9ec0]+768]+6b4]` 起 **2000 个 int32**
- 结构：**每 50 个 = 1 波，共 40 波** → 每波**最多 50 只**
- 生存无尽每轮仅 20 波 → **只用前 1000 个值**
- **在选卡界面就已确定**；退出重进选卡可刷新（"**无痕 S/L**"）
- 刷新时**严格按列表预设顺序**依次生成
- 老虎机/宝石迷阵等无限模式：第 41 波起**循环第 40 波**

### 3.1 影响出怪列表的四个因素
**权重 → 级别 → 阶数 → 红眼数量上限**

## 五、级别上限（决定一波能有多强）

```
每波级别上限 = int( int((当前波数 + 已完成选卡数 × 20) × 0.8) / 2 ) + 1
旗帜波：在此基础上 × 2.5，向零取整
```

**意义**：级别总和封顶 → 早期波次不可能出红眼×N 的组合。
`级别 10` 的僵尸（白眼/红眼/僵博）非常"贵"，一波放两只就吃掉 20 点预算。

## 七、红眼数量上限（"变速"的开关）

- 已生成红眼总数**达到上限后，非旗帜波不再出红眼**（立刻生效）
- 上限：初始 **0** → 轮数 5 起每轮 **+1** → 轮数 54 起**固定 50**

> 这条就是 `02` 里说的"变速"：**红眼累计 ≥ 50 只后，非旗帜波不再出红眼**。
> 有红无白关里，后半程明显变快，根因在此。

## 九、出怪选行（僵尸走哪一路）

> 原文要求"一定的数学知识"。这里只保留可用的结论。

### 9.1 三个状态量
每行有 `Weight_i`、`LastPicked_i`、`SecondLastPicked_i`，后两者初值 0。

**插入事件**（第 j 行出了怪）：
```
① 对所有 Weight_i > 0 的行：LastPicked_i += 1，SecondLastPicked_i += 1
② SecondLastPicked_j = LastPicked_j
③ LastPicked_j = 0
```

**抽取事件**：
```
WeightP_i = Weight_i / ΣWeight
PLast_i       = 6·LastPicked_i·WeightP_i + 6·WeightP_i − 3/4
PSecondLast_i = SecondLastPicked_i·WeightP_i + WeightP_i − 1/4
SmoothWeight_i = WeightP_i × clamp(PLast_i + PSecondLast_i, 0.01, 100)
```
然后按 SmoothWeight 加权抽取；**前 5 行全为 0 时必定选第 6 行**。

### 9.2 三条推论
1. **没有可出行时，僵尸一定在 6 路出现**（所有行权重 0 → P₆ = 1）。
2. **样本足够大时，平均概率只与权重有关**，可忽略 LastPicked / SecondLastPicked。
3. LastPicked 只与"行被选中的顺序"有关。

> **实战用法**：做全局分析（比如算某路压力）时，直接按权重比例估算即可；
> 做单局推演（比如"这波下路会不会堆满"）才需要平滑权重。

### 9.3 合法行（哪些行不能出）

通常不合法：
1. 行 > 6 或 < 1
2. 无草皮之地以外的**裸地行**
3. 非"泳池浓雾"类关卡（含无草皮之地）的**第 6 行**
4. 无草皮之地的**第 1 行与第 5 行**

特殊僵尸额外限制（选摘）：
- **高地行**：冰车、雪橇队不合法（正式版已废除高地行）
- **水路**：只允许普僵/旗帜/路障/铁桶/潜水/海豚/气球/植物僵尸
- **水路（波数 < 5）**：只允许海豚、潜水
- **非水路**：海豚、潜水不合法
- **冰道消失倒计时为 0** 的行合法，但**雪橇小队**不合法
- **非无尽关卡第 1 行**：白眼、红眼不合法
- **非后院**：舞王需要"草地 + 1≤行≤6"（无草皮之地的裸地**合法**）

### 9.4 选行流程（顺序固定）
```
钉耙 → 行类型 → 保护传送门 → 隐形食脑者 → 最后一波 → 推车 → 权重
```

**推车阶段（MowerTest）**是生存无尽里最有用的一条：
```
MowerTest = 当前波数 − 该行上次丢车的波数
MowerTest ≤ 1        → Weight = 0.01   （几乎不再来）
1 < MowerTest ≤ 2    → Weight = 0.50
其它                  → Weight = 1
```

> **推论：某行刚丢过小推车，接下来 1~2 波该行压力会大幅下降。**
> 这对"破阵后还能不能续"的判断很关键——崩了一路不代表立刻再崩一次。

## ★ 饱和出怪：每波 50 只（2026-10-18 补，来源 wiki《技术:出怪机制》）

> 这一节解释了为什么"每一波每一路、除红眼外每种僵尸都会来几只" —— **对策不能省**。

### 出怪列表是唯一的数量来源

> "完整的出怪列表长度 2000……**每 50 个为 1 波，总共记录 40 波。因此，每波至多生成 50 只僵尸。**
> 若出怪列表中留空，则对应波次会生成少于 50 只。
> **每波僵尸刷新时，游戏会严格按照出怪列表预先设定的顺序依次生成对应僵尸。**"

```
生存无尽每轮 20 波 → 只用前 1000 个值
列表在选卡页面就已确定；退出重进可刷新（"无痕 S/L"）
```

### 列表怎么被填满：权重 → 数量

权重不直接等于数量，而是**加权随机决定下一个填谁**，直到**本波级别总和逼近级别上限**为止：

```
每波级别上限 = int(int((当前波数 + 已完成选卡数 × 20) × 0.8) / 2) + 1
               旗帜波 ×2.5，向零取整
```

**饱和之后（f ≥ 85）级别上限不再起限制作用 → 列表被填满 → 每波 50 只。**
50 只摊到 6 路，每路 8~9 只，再按权重分配种类 —— 这就是"每种都会来"的来源。

### 三个饱和阈值（原文）

| flags | 含义 |
|---|---|
| **47f** | 阶数不再起限制作用 |
| **85f** | 级别上限在**统计意义**上不再起限制作用 |
| **109f** | 红眼数量上限不再起限制作用 |
| **126f** | 级别上限在**严格意义**上不再起限制作用 |

### 红眼数量上限（原文）

> "已生成的红眼总数达到上限后，非旗帜波不再出红眼，立刻生效。
> 上限初始为 0，**轮数=5 起每轮 +1**，轮数=54 起固定 50。"

（轮数 = 选卡时已完成 flag 数 / 2 − 1）

### 阶数：决定"从第几波才会出现"

| 阶 | 僵尸 | 最早出现 |
|---|---|---|
| 一阶 | 普、路障、铁桶、读报、雪人 | 第 1 波 |
| 二阶 | 撑杆、铁门、橄榄、舞王 | 第 5 波 |
| 三阶 | 潜水、海豚、冰车、小丑、气球、矿工、跳跳、梯子、投篮 | 第 10 波 |
| 四阶 | 白眼、红眼 | 第 15 波（轮数=9 起每轮 −1，23 起固定 1） |

### 对做阵/做验证的直接结论

```
① 别抱侥幸：饱和后每波 50 只，**每一路每种都会来**
   → 任何"这个僵尸来得少所以可以不管"的假设都是错的
② 前 9 波是"一二阶"的天下，三阶僵尸第 10 波才登场
   → w1~w9 的压力主要来自 普/路障/铁桶/橄榄/铁门/舞王/撑杆
③ 蹦极权重 1000，且**仅旗帜波生成** → 只可能在 w10 / w20 出现
④ 红眼上限随轮数线性增长，轮数=54 起固定 50
```

> 验证器里的实现：`tools/trackcheck/spawn.py`（加权随机 + 级别上限 + 阶数门控 + 每波≤50）。
