## ★ 阵型字符串两套格式（2026-10-22 破解，长期结论）
- **PvZ Tools（旧，明文）**：`钉耙行, ID 行 列 awake f5 f6, …`
  - `ID` = **十六进制 SeedType 直接值**（`2A`=忧郁菇、`10`=睡莲、`2C`=冰瓜、`A`=大喷菇、`E`=寒冰菇）
  - **`1E`=南瓜壳、`30`=梯子**（不是模仿者）；`awake` 只对蘑菇有意义
  - 顺序：底座 → 主植物 → 南瓜 → 梯子；**不支持模仿者主植物与墓碑**
  - ⚠️ 用我们自己的编码器 re-encode 会**多出**原串没写的睡莲（源串里 3-4/4-6 的香蒲没写），
    不是逐字往返 —— 别再把"内容一一对应"说成"逐字一致"（0.2.3 犯过这个错）
- **PvZ Toolkit（新）**：RFC1437，Base64 → 整段（含 RS 字节）异或 0x54 → zlib + RS
  （RS 放错在异或外面会得到 rake 恒 5 / 场景恒 6）
- 工具里 `layout.py` 两套都支持，设置页选、导入自动认格式。

## 已知资料坑
- 维基 `id=技术` 不是有效页面（技术是命名空间）。
- 旧读本 `参数×2=基础运算量` 与自身例子矛盾 → 逐波计数为准。
- A / A' 已统一为 A=樱桃、A'=辣椒；旧读本的 `A1=辣椒` 是历史写法。
- **命名与参数以 `docs/知识库/08` 为准**（双轨制）：C 系用"过怪量"，其它系用"加速×1+减速×2"。
- 节奏例的波长不是定义的一部分，不同文献给不同数字是各自阵型的取值。
- 精确数据条目里约 8 张关键表格是图片，未提取。
- pvz.tools 的 endless 页三大板块全标"已废弃待删除"，只当阵型名录用。
- **脚本框架用 AvZ，不要用 pyvz**（作者已弃用，6 年未更新）。
- **阵型代码 ID 是十六进制、按十进制常量解析**：`0x0A`=10=大喷菇（**不是荷叶**）、`0x10`=16=荷叶（**不是路灯**）、`0x1E`=30=南瓜、`0x25`=37=伞、`0x29`=41=双子向日葵、`0x2A`=42=忧郁菇、`0x2C`=44=冰瓜、`0x2F`=47=炮、`0x30`=48=模仿者。**解析前先用南瓜/炮反验一遍。**

## PVZ 硬常识（易错，务必记住）
- **紫卡基础价 / 实际单株价**（含基座）：忧郁菇 150/225（基座大喷 75）、香蒲 225/250（荷叶 25）、冰瓜 200/500（西瓜 300）、双子 150/200（向日葵 50）、机枪 250/450（双发 200）、地刺王 125/225（地刺 100）、玉米炮 500/700（玉米×2）、吸金磁 50/150（磁力菇 100）。
- **绿卡易错价**：窝瓜 **50**、大喷菇 **75**、双发 **200**、咖啡豆 **75**、毁灭菇 **125**、辣椒 **125**、樱桃 **150**、南瓜 **125**、伞 **100**、荷叶 **25**、大蒜 **50**、小喷 **0**、花盆 **25**、三叶草 **100**、西瓜 **300**。完整 40 张见 `05` 第十二节。
- **无尽模式紫卡会涨价**：同种紫卡每多一株 **+50**，被摧毁后回落。第 n 株 = 基础价 + 50(n−1)；种 n 株总价 = n×基础价 + 50·n(n−1)/2。**绿卡不涨。**
- **白天用一次核 = 200**（毁灭菇 125 + 咖啡豆 75）；**点一次存冰 = 75**（咖啡豆）。
- **场外区**：第 10 列（及第 0 列）属场外。僵尸"可伤"条件是**防御域左端 ≤ 800**（精确数据），所以刚出生的僵尸只有部分判定域进场，"在场外"≠"打不到"，但**打不完整**。
- **读轨道先读卡 CD，再读运算量**：顺序常被咖啡豆 CD 逼出来（如 C4io 的 N|AA'|I）。
- **忧郁菇对"蹦极"的判定框是 3 行 × 5 列**（对普通僵尸只有 3×3）→ 落到 2-3 的小偷，1-1 到 3-5 都打得到。这才是"**2 曾杀蹦极**"能成立的机制原因；冰杀火力下限 = 两曾（或 一曾 + 一瓜 + 任意输出）。蹦极停留 300cs、抓取 63cs。
- **投篮（投石车）的落点在底线（1、2 列）**，两条波长红线：**加速波 7.46s / 冰波 19.29s**。伞罩住底线即免疫 —— 所以"怕不怕投篮"看的是**底线有没有伞**，不是波长够不够短。多数阵的加速波（9~12s）本来就超 7.46s。
- **伞（叶子保护伞）覆盖 3×3 且含自身格**。放在**第 2 列**才能罩住第 3 列的关键植物；放第 1 列只有 4 格有效面积。两把伞可分别罩住相邻两路后场。
- 无炮的冰是稀缺资源，按**可逆性**排序花：不可逆损失 > 可逆磨损 > 节奏舒适度。

## ★「偷盲」的定义（2026-10-18 用户纠正）
**偷盲 ≠ 伞没罩到的格子**。偷盲 = **「无法冰杀蹦极的格子」**（伞或冰杀，有一条能用就不算）。
冰杀两条定式【维】：**① 两曾；② 一曾 + 一瓜 + 任意其他输出**。
判断要不要冰杀，先算账：冰 75；**锁 1 个大喷不冰，≥2 个大喷才冰；花/曾必须冰**。


## 三层结构
`01~07` 玩法层（怎么打）｜`08~10` 理论层（为什么/能不能不这样打）｜`11~12` 工程层（量化验证）。

- **★ AoE 阵永远不要用"总血量 ÷ dps"判断可行性**（2026-10-18 用户纠正）：
  曾哥对 3×3 内每只僵尸**各打全额 80（1 轮）**、大喷前方 4 格各打 20，都无衰减。
  → 僵尸越多总输出同比放大，**每只受到的 dps 不变**，"来一群"和"来一只"是同一个时间问题。
  → 唯一正确判据：`T_kill（血÷该点 dps） ≤ T_move（走到该路最靠前的 CORE）`。
  → 实测印证：2 路 21 只 → 41.0s 全灭；32 只 → 42.9s 全灭（数量 +50%，时间 +5%）。
  推论：2 路 4 级 IO "红眼来多少都能杀"；5 路 3+ 级 IO 弱一档（21 只跑掉 3 只），需 5-7 一张垫材。

- **★ 攻击判定的正确形式是「框相交」，不是「僵尸中心在范围内」**（2026-10-19 用户）：
  - 僵尸受击框（[精 二] 左行僵尸）：普僵宽 42、巨人宽约 70
  - **★ 判据是"位置"不是"体型列数"**（2026-10-19 用户）：
    普通站在 x 列**正中央**只吃 x−1/x/x+1 **三列**，走到**左半边**才跨进 x−1、吃到 x−2（四列）；
    **巨人正中央就已经跨格**，所以正中央就四列。
  - 模型取值：普通 `(+10, 42)`、巨人 `(-35, 70)`（相对僵尸 x 的偏移+宽度）
    ⚠️ off 必须 > 0 才能复现"正中央 3 列"；居中(off<0)会让普通正中央就吃 4 列
  - 植物射程是**攻击框**，僵尸受击框与之**交集非空**即命中
  - 推论：看似 61 像素的冰瓜溅射，实际有效范围要宽 40~70（沾边就算）
  - 可伤条件"防御域左端 ≤ 800" → 普僵 x ≤ 764，巨人 x ≤ 800
  - ⚠️ 旧模型用的 `[x−36, x+36]`（宽 72 居中）是错的，它让僵尸一出生就进所有射程
- **攻击间隔**（[精 5.1]）：大部分植物 1.36~1.50s｜投掷类 2.86~3.00s｜**忧郁菇 1.86~2.00s**｜地刺王 1.01s
- **冰瓜溅射**：574/n（n **不含被直击那只**），取整，**上限 26、下限 1**

## 0.2.30（2026-10-23）— 预演-回溯（lookahead）
用户口径：
> 「先保证每条被覆盖的路都至少切到最靠前那只」是有条件的：模型基于计算，具有
> 「预演-回溯」能力；若能估算最靠前的怪是否在破坏 core 之前被 io 打死，则可以不管，
> 否则必须炸到。简化模拟工具一定要有部分预演-回溯能力（可以短暂的 DFS 或 BFS），
> 在轨道下一定可以找到极优解（在固定行上滑动）。广泛而言，所有用户没有定死的操作
> （落点滑动、救场、其它灵活功能）都可以通过搜索得到极优解。

### 新增 `tools/trackcheck/lookahead.py`
- `dps_by_cell(sim, row)`：用**场上活着的**植物算每格实际 dps。
  `_covers()` 支持 rows=3（忧郁菇）/ rng=[lo,hi]（大喷·地刺）/ rng=None（冰瓜·机枪·香蒲）。
- **`IO_DPS_HAIRCUT = 0.75`**：`dps_by_cell` 假设"每株 100% 在打这只、从不换目标、
  自己不会被吃"，实战做不到 → dps 打 75 折，让"可以不管"的结论**保守**。
- `io_eta(sim, z)`：前向推演，返回 `(会不会死, 还需 cs, 最多推到第几列)`。
  逐格积分（用 `_speed_of` 已含减速），不逐 cs → "短暂的推演"。
- `best_aim(...)`：有界搜索（候选 ≤40：每只僵尸反解列 ±0.5 + 0.5 列网格），
  **字典序**取优：① 硬约束「覆盖到的每一路，最靠前那只若必须炸就必须被打中」
  ② 打死多少（冰车/投篮/巨人 ×3）③ 打掉多少血 ④ 离第 8 列别太远。

### 接线
- 玉米炮 `[行,'threat'|'front']`、樱桃 `[行,'front']` → 都改走 `best_aim()`。
  经典八炮实测仍稳定选 8.0（说明"1 路最靠前有冰瓜兜底"的判断成立）。
- `plan.probe_target()`（救场）：先推演一次，只有"① 还在 1.5 格以外
  ② 会死在摸到植物之前"才判"不用出手"。省下的次数记 `report['la_skip_n']`
  （顶层 + `end_state` 各一份）。

### 踩过的坑（重要）
1. **门控曾是死代码**：`probe_target()` 里用了 `D.EAT_OFFSET`，但 `plan.py` 只在别的
   函数里局部 `import data as D`；这里没有 → `NameError` 被 `except Exception: pass`
   吞掉 → 门控从未生效。**真相**：之前记录的"10/20→7/20→10/20"三组数据其实都是
   "无门控"的结果。教训：**`except Exception: pass` 会把新功能静默变成死代码**，
   调试时要先确认"这段代码真的跑了吗"（往 stderr 打点 / 数计数器）。
2. **推演不能按"此刻速度"算**：僵尸此刻被冰冻 → 按半速积分 → 推演"1200cs 后死"，
   但 400cs 后冰化了按全速走 → 把 1-5 炮啃了。`io_eta` 现在按 `_base_speed(z)`
   （未减速速度）积分 = 最坏情况。
3. 门控语义取用户原话"在**破坏 core 之前**被 io 打死"：
   `need_cs < t_reach + 剩余血量 × LA_EAT_TRUST`，`LA_EAT_TRUST = 0.0`
   （必须死在摸到植物之前）。`z.x - c.x > 120`（已贴上来的必须出手）保留。

### 英文全覆盖的机制（这套要记住）
- `i18n_bulk.py`：约 800 条**整串**词条（界面 HTML/JS、模型清单备注、报告页文案、
  阵解目录、内置示例阵解），`localize()` 里**最长整串最先命中**；
  `_clean_bulk()` 丢掉"植物/僵尸名的片段"（`炮` ⊂ `玉米炮`）与 1 字词。
- `JS_LITERALS`：JS 里 `'距' + x + '生效+'` 这种**引号内片段**，按 `'词'` 精确替换；
  ⚠️ 必须先做它、再做标识符保护，否则 `title="南瓜"` 被保护后整串 HTML 匹配不上。
- `localize_obj()`：JSON 载荷只翻**显示字段**（`_TEXT_KEYS` = note/label/trad/new/group…），
  `_KEEP_KEYS`（deck/cards/do/op/role/zombie/field/mimic…）不翻，名字再靠 `_is_identifier()` 兜一层。
  已用"本地化前后结构差异只允许出现在 note/name/id"单测盯住。
- `TR_EXTRA`：`炮`/`卡`/`自定义`/`垫材2` 这些 1~2 字词条只给 `tr()`（整串精确查表）用，不进 WORDS。
- 前端 `META.enMap` + MutationObserver：**文本节点整串精确匹配**替换（value 不动），
  并暴露 `window.tcShow(s)` 给 JS 自己拼句子时用。
- `spec_text_en.py`：6 篇「i」按钮格式说明的英文版；`plan.spec_text()` 按语言挑。
