## 二、Board 关键字段（研究最常用的那些）

> `B + xxx`，全部 4 字节整型（另有标注除外）。

### 2.1 波次与刷新（核心）

| 偏移 | 含义 | 用途 |
|---|---|---|
| `5560` | **阳光值** | 测经济 |
| `5568` | 游戏计时（不含选卡停留） | 测波长 |
| `556C` | 游戏计时（含选卡停留） | 测整场 |
| `5574` | **产生三人组倒计时** | 珊瑚/空降 |
| `557C` | **当前所在波数** | 波次判定 |
| `5580` | **已刷新的波数** | 同上 |
| `5594` | **达到刷新条件的血量** | 与 5598 相除 = **本波实际阈值** |
| `5598` | **本波总血量** | 同上 |
| `559C` | **下一波僵尸倒计时** | 预判炸/预判冰的物理时钟 |
| `55A0` | 下一波倒计时初始值 | — |
| `55A4` | 大波（旗帜）僵尸刷新倒计时 | — |
| `5618` | **水面冻结倒计时** | 冰消珊瑚 |
| `561C` | **生存模式出怪种子** | 复现出怪 |

> **`5594 / 5598` 就是 `02` 里那个"0.5~0.65 随机阈值"的实际值**。
> 想验证某一波会不会刷新，读这两个数比猜靠谱得多。

> **`559C` 是轨道计算最该用的时钟。** `Prejudge/Until` 本质就是在锚定它。

## 五、脚本框架：用哪个

| 框架 | 语言/实现 | 状态 | 精度 |
|---|---|---|---|
| **AvZ**（AsmVsZombies） | C++ 接口 + 汇编注入 | ✅ **官方推荐** | 高，能读内存、能改时钟 |
| pyvz（pvz.py） | Python + Win32 模拟键鼠 | ❌ 作者已不建议使用 | 低；页面 6 年未更新 |

**AvZ 地址**：`gitee.com/vector-wlc/AsmVsZombies` / `github.com/vector-wlc/AsmVsZombies`

**为什么还要看 pyvz**：它的 API 命名与思路清晰，是理解"键控脚本长什么样"的最好教材。
AvZ 的接口设计与之神似，迁移成本低。

### 5.1 pyvz 的局限（也是所有"模拟键鼠"路线的局限）

- Win32 模拟 + Python + Windows 非实时 → **精度不足**
- 咖啡豆与模仿者寒冰菇生效时间不确定 → **100% ICE3 不可能实现**
- 不支持：操作乱序、铲种炮、非定态、波长设定、精准冰三、女仆秘籍、植物修补

## 六、pyvz / AvZ 核心 API

### 6.1 内存
```python
ReadMemory(data_type, *address, array=1)      # 多级偏移
WriteMemory(data_type, values, *address)

ReadMemory("int", 0x6a9ec0, 0x768, 0x5560)    # 阳光 → 8000
ReadMemory("byte", 0x0041d7d0, array=3)       # 读数组
```

### 6.2 时间（**最核心的四个函数**）

| 函数 | 作用 | 精度 |
|---|---|---|
| `Sleep(cs)` | 线程睡眠 | 0.1cs，受 OS 调度影响 |
| `Delay(cs)` | 读**游戏内部时钟** | **1cs，更准**；暂停时同步暂停 |
| `Prejudge(rel_cs, wave)` | 每波开始调用一次，**锚定本波刷新时刻** | — |
| `Until(rel_cs)` | 等到"相对本波刷新的差值"，须配合 `Prejudge` | — |

**取值范围**：
```
Prejudge：建议 [-200, 400]
          第一波最早 -599，旗帜波最早 -750（设边界值可能报错）
Until：   建议 [-200, 2300]
          多个 Until 连用必须按时间先后排序（否则静默出错）
```

### 6.3 操作封装
```python
Card(seed, *crood)          # 用卡
Shovel(*croods)             # 铲（坐标可小数，用于南瓜偏移）
Pao(*croods)                # 发炮，支持多落点
RoofPao(*croods)            # 屋顶修正飞行时间，仅前场约 7~9 列
Skip(num)                   # 按炮列表顺序跳炮（9/19 波收尾）
```

### 6.4 自动化
```python
AutoCollect(collect_items, interval_cs)
IceSpots(spots, total)      # 存冰；临时位放列表后面
Coffee()                    # 点冰（咖啡豆唤醒存冰）
@RunningInThread            # 装饰器：独立线程
MouseLock()                 # 唯一鼠标锁，with 语法
```

## 七、时机计算公式（**这一节最值钱**）

> 全部来自 pyvz 文档，可直接套。

| 场景 | 公式 | 例 |
|---|---|---|
| 刷新前 95cs | `-95` | `Until(-95)` |
| 刷新后 180cs | `180` | `Until(180)` |
| 想在某 cs 生效的炮，何时发射 | `生效时刻 − 373` | `Until(444-373)` |
| **白天点下一波预判冰的咖啡豆** | `波长 + 冰生效偏移 − 298` | `601+20-298` |
| **夜间种下一波预判复制冰** | `波长 + 偏移 − 100 − 320` | `1350+5-100-320` |
| **减速波激活炸** | `波长 − 200 − 373` | `1200-200-373` |
| **白天减速波核 + 点咖啡** | `波长 − 200 − 100 − 198` | `1150-200-100-198` |
| 收尾拖满红字 | `4500-5` → `Until(4500-5)` | — |
| 最后一大波白字 | `Until(5500)` | — |

**记法**：`波长 − 刷新真空(200) − 生效延迟`。
- 炮生效 **373**
- 核生效 **298**（100 释放 + 198 唤醒）
- 冰生效 **298**（白昼）/ **100**（夜间）
- 咖啡豆唤醒 **198**
- 模仿者变身 **320**

## 八、工程实践清单

### 8.1 取消点炮限制（"炮粘手"）
点炮后 30cs 内，落点与点炮位置距离 < 100 则发不出。
```python
WriteMemory("int", 0x00679300, 0x0040fced)   # 1.0.0.1051
WriteMemory("int", 0x00679458, 0x0040fcdd)   # 1.2.0.1065
```

### 8.2 常用改内存
```python
WriteMemory("short", 0x00eb, 0x0054eba8)     # 允许后台运行
WriteMemory("byte", 0x71, 0x0052dfe8)        # 舞王伴舞转身后不前进
WriteMemory("unsigned short", 0xe990, 0x0041d025)  # 僵尸死后不掉钱
WriteMemory("unsigned short", 0xd231, 0x0041a68d)  # 浓雾透视
WriteMemory("int", 8000, 0x6a9ec0, 0x768, 0x5560)  # 阳光 8000
WriteMemory("int", int(2020/2), 0x6a9ec0, 0x768, 0x160, 0x6c)  # 完成 2020 面旗帜
```

### 8.3 调试省时三阶段
```
阶段一：手动选卡、开场即退出、存档设只读 → 调 w1~w9
阶段二：取消只读 → 回主菜单 → 再设只读 → Skip 炮数 → 调 w10~w20
阶段三：改用未选完卡的存档，启用选卡 → 从头完整跑
```

### 8.4 测操作耗时（两种）
```python
t0 = ReadMemory("int", 0x6A9EC0, 0x768, 0x5568)
Sleep(100)
t1 = ReadMemory("int", 0x6A9EC0, 0x768, 0x5568)
print(t1 - t0)     # 单位 cs
```
或用 PotPlayer 按 `D`/`F` 逐帧测（建议 60/100 帧录制）。

### 8.5 一条硬规矩
> **多个 `Until` 必须严格按时间递增书写。** 写反了不报错，直接静默跑错，
> 而且错误会累积到整波。这是新手最常见的"脚本莫名其妙"来源。
